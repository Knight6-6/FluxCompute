## 读法建议

- **第一次读**：01 → 02 → 04。这三份串起来是"数据怎么描述 → 怎么在图上流动 →
  怎么执行"的主线。
- **要改算子或内核**：03。里面有几条容易被误改的语义约定（单位元、NaN、空集）。
- **要碰性能**：05 先看第三节"测量方法本身的坑"，再看结论。翻车记录比数字更有价值。
- **想知道为什么长这样**：问题记录。每条都是实际踩过的，不是设想出来的。

## 约定

文档记录的是**设计与实现中真正遇到过的问题**，以及当时的取舍和依据。
不含笔误一类的低级问题——那些看 diff 就够了。

两条记录原则：

- 有实测数据的写数据，没有的写明"未验证"，不把推测写成结论；
- 取舍要写清**为什么不是另一个方案**，否则后来者会把取舍当成疏漏
  重新讨论一遍。
